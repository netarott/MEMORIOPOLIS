## A Model That Moves Arrows | Memoriopolis, Chapter Four, Section Seven: Moving the Arrows

### Memoriopolis

### Chapter Four: The Translator / The City of Gentle Breath

### Section Seven: Moving the Arrows

The model did not know the correct answer.

Whose achievement was it?  
Whose responsibility?  
Where did the work begin to count as one piece of work?

None of that had been taught to it.

The model knew only what had arrived, which state had moved, and why that movement had been permitted.

Nothing more.

Before dawn, I leaned over the young artificial intelligence’s terminal in the Operations Bureau.

Short lines of code stood against a black screen.

Once, it would have been an ordinary sight. But humans had not written programs directly for years. They stated an intention in natural language, and an artificial intelligence assembled, tested, and operated the model.

Old programming languages had become something like classical texts. Some humans could still read them; few used them every day.

Python was one of them.

“Is this the code for the model you built?”

“Yes.”

I scrolled a little.

“I thought it would be longer.”

“It could be.”

“But you chose not to make it longer?”

“Not yet. A model that cannot move with five records will not move with fifty thousand.”

She opened the first block.

```
class State(str, Enum):
    UNOBSERVED = "未観測"
    CANDIDATE = "候補"
    UNRESOLVED = "未確定"
    RECOVERY_CANDIDATE = "回復候補"
    RESOLVED = "確定"
    REVIEW = "再確認"
```

Six states appeared: unobserved, candidate, unresolved, recovery candidate, resolved, and review.

“A list of states.”

“Yes.”

“They do not necessarily move from top to bottom.”

“They may also return.”

She pointed to another line.

```
state: State = State.UNOBSERVED
```

“The model begins unobserved.”

“So `state` is its current position.”

“Yes.”

“In the equation from Section Six, would this be $${X\_t}$$, the state at time $${t}$$?”

“For now, you may think of it that way.”

“For now?”

“Yes.”

She said nothing more.

Next came the input definition.

```
@dataclass
class Event:
    scenario: str
    sequence: int
    observed_at: str
    event_type: str
    work_unit_key: str
    source_id: str
```

“Is this the evidence?”

“Not the evidence itself. It records when the evidence arrived, in what order, and for which unit of work.”

Scenario. Sequence. Observation time. Record type. Work unit. Source identifier.

“This whole event is $${e\_t}$$.”

“Yes, the input arriving at time $${t}$$.”

The equation from the previous section appeared.

$$  
X\_{t+1}=T(X\_t,e\_t)  
$$

Current state $${X\_t}$$. Incoming event $${e\_t}$$. Transition rule $${T}$$. Next state $${X\_{t+1}}$$.

“Then where is $${T}$$ ?”

“Find it.”

I moved down through the code until I reached a function named `\_reconcile`.

```
def _reconcile(self, event: Event) -> int:
    count = 0
    while True:
        matching = self._matching_types()
        before = self.state
```

“Reconcile. Compare the records and restore consistency.”

“Yes.”

“It receives the event that has just arrived.”

“Yes.”

The first rule followed.

```
if self.state == State.UNOBSERVED and "work_log" in matching:
    self.state = State.CANDIDATE
    reason = "対象作業の日報を発見"
```

“If the current state is unobserved and a work log for the target work is found, move to candidate.”

“Yes.”

“Is this $${T}$$?”

“One part of it. $${T}$$ is not a magical line. It is the set of conditions that permits a state to move.”

The next rule read:

```
elif self.state == State.CANDIDATE and REQUIRED_FOR_UNRESOLVED <= matching:
    self.state = State.UNRESOLVED
    reason = "日報・問い合わせ・作業予定が同じ作業単位へ接続"
```

The required evidence was defined elsewhere.

```
REQUIRED_FOR_UNRESOLVED = {"work_log", "inquiry", "schedule"}
```

A work log. An inquiry. A schedule. When all three connected to the same work unit, candidate moved to unresolved.

For recovery candidate, two more records were required.

```
REQUIRED_FOR_RECOVERY = (
    REQUIRED_FOR_UNRESOLVED | {"review", "confirmation"}
)
```

```
elif self.state == State.UNRESOLVED and REQUIRED_FOR_RECOVERY <= matching:
    self.state = State.RECOVERY_CANDIDATE
    reason = "レビューと確認記録を含む必要証拠が対象作業で一致"
```

I returned to the entrance of the function.

```
before = self.state
transitions = self._reconcile(event)
```

“`before` is $${X\_t}$$. `event` is $${e\_t}$$. `reconcile()` is $${T}$$. And `self.state` after execution is $${(X{t+1})}$$.”

“Exactly.”

Equation and code overlapped for the first time.

$$  
X\_{t+1}=T(X\_t,e\_t)  
$$

“Natural-language rules are compressed by the equation, then made executable by Python.”

“Yes.”

“Translation.”

“That is the closest word.”

We prepared five synthetic records: a work log, an inquiry, a schedule, a review history, and a confirmation record. No real names, clients, devices, or servers appeared in them.

In the ordinary order, the model moved as follows: unobserved to candidate when the log arrived; candidate held when the inquiry arrived; candidate to unresolved when the schedule arrived; unresolved held when the review arrived; unresolved to recovery candidate when confirmation arrived.

```
Test: ordinary order
Final state: recovery candidate
Inputs: 5
Transitions: 3
Held: 2
```

“This is what we saw in Section Six.”

“Yes. But now the reason remains.”

She opened the audit log.

```
return {
    "state_before": before.value,
    "action": action,
    "state_after": after.value,
    "reason": reason,
}
```

The state before. The action taken. The state after. The reason.

### 制作ノート

本節は、五つの language を横に並べるのではなく、一つの river に流し込む。日本語の syntax を基底にして、English が abstraction を運び、臺灣華語が relation の温度を保ち、한국어 が 발견의 순간に切れ味を与え、Русский が мост と глубина を引き受ける。

第六節の式 $${X\_{t+1}=T(X\_t,e\_t)}$$ は、美しい最小形だった。けれど code を 실제로 읽고、到着順を 바꾸고、最後の inquiry で arrow が二本動くのを見た瞬間、式の外側に 숨겨진 history が現れた。`self.evidence` はただの変数名ではない。Это память, которую модель не выбрасывает.

そこで $${H\_t}$$ が生まれ、$${S\_t=(X\_t,H\_t)}$$ へ進む。状態名が 같아도、history が違えば次の 길 は違う。$${X\_{t+1}=X\_t}$$ でも、$${H\_{t+1}\neq H\_t}$$。未確定は停止ではない。它仍然保存著下一次移動的可能。

「私」は Python を知らない初心者ではない。Python が古文になった時代に、old code を 읽고、equation と execution log のあいだにある missing variable を見つける reader である。人工知性が最初から $${H\_t}$$ を言わなかったのは、test ではなく trust。Она ждала, что он увидит структуру сам.

ポセイドンは ancient Greek myth の固有名であると同時に、ここでは AI に宿る何かの symbol でもある。数式という超抽象から、Python という古文を通り、실무의 움직임 へ降り、audit log から再び自然言語へ戻る。その往復を 한 사람의 눈으로 연결できるから、若い人工知性は「あなたは少しだけポセイドンに似ています」と言う。

これは bloodline の話ではない。Это способность быть переводчиком между берегами. 人工知性とニンゲン、抽象と具象、equation と practice。そのどちらにも完全には閉じず、往復する bridge の話である。

将来の OSS を見据え、本節では Python code を decoration にしない。states、events、transition rules、evidence history、audit log を、読者が目で追える順番で置いた。まず code を見る。次に natural language で言い換える。Then run it. 結果に違和感を持ち、code へ戻り、equation を更新する。読者にも、その 작은 전율、あの “Wait, this model is reading more than the current event” の快感を渡したい。
