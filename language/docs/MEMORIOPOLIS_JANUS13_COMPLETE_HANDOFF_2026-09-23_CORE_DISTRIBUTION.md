## 7. 活動方針の重要な変更

### 旧来の外向き活動

- Noteの継続更新
- YouTube制作
- SNS向けの整形
- GitHub Pagesの作り込み
- 閲覧数や反応の追跡

これらは当面の必須工程にしない。

多言語クリエイターという肩書きを先に説明し、広く認知してもらうことを目的にしない。外部メディアに合わせるためのタイトル、サムネイル、更新頻度、短文化、導入説明などへ制作時間を割かない。

### 新しい中心線

```text
読む
  ↓
現代日本語で考える・書く
  ↓
Concept候補を発見する
  ↓
JANUS-13へ展開する
  ↓
Ankiで変換訓練する
  ↓
カバー率と想起状態を観測する
  ↓
次の読書・創作へ戻す
```

### 各要素の役割

- GitHub：正本、変更履歴、静かな公開場所
- Markdown：日々の航海日誌、読書記録、作業記録
- Novel：物語世界からConceptを供給する
- Essay：現実世界、ニュース、読書から日常語と思考語を供給する
- Concept ID：各言語・画像・場所・物語を結ぶ共通座標
- Anki：変換訓練装置
- FSRS：復習時期を制御する
- カバー率：次に整備すべき領域を示す地図

GitHubは閉じた場所ではない。縁のある人が必要に応じてたどればよい。Pagesが必要になった場合も、リポジトリの体系が十分に育ってから生成できる。

## 9. JANUS-13の方法論

### Concept IDの役割

Concept IDは翻訳語の番号ではない。異なる記憶表象が合流する共通座標である。

```text
Concept ID
  ├─ 固定された場所
  ├─ Concept画像
  ├─ Novelの出来事
  ├─ 現代日本語の説明
  ├─ 近代日本語の表現
  ├─ 各言語の語形
  ├─ 各言語の音声
  └─ 各言語固有の意味範囲
```

### 伝統的記憶術との統合

- 固定地点：場所法
- Novelの出来事：ストーリー法
- Concept画像：視覚的手掛かり
- TTS：音響記憶
- 文字：語形と正書法
- Anki：アクティブリコール
- FSRS：分散学習
- Concept ID：すべてを同じ住所へ戻す共通座標

JANUS-13は、古来の記憶術をAIで置き換える活動ではない。伝統的記憶術が意味の構造を作り、ITが反復・整列・多言語展開を支える。

### AIとインターネットの役割

AIとインターネットによって、次の初稿作成・調査コストが下がった。

- 対応語の調査
- 翻訳初稿
- 例文作成
- 例文解説
- 発音情報
- 表記体系の確認
- CSV整形
- カード設計
- 言語間比較

ただし、人間がConceptとの対応、意味範囲、自然さ、文脈、想起可能性を確認する。AI出力をそのまま正本にしない。

## 10. 多言語能力についての現在の仮説

「人間が扱えるのは母語だけ」と断定するのではなく、現在は次のように整理する。

> 成人の多言語能力とは、複数の完全な母語を所有することではなく、個人の支配的な言語・概念基盤から、目的別に形成された複数の言語表象へ、適切かつ迅速にアクセスできる変換体系である。

JANUS-13は日本語中心の外国語群である。ただし、最終的には外国語から毎回日本語訳を経由するだけでなく、外国語の語形や音声からConceptへ直接到達する経路を育てる。

```text
初期
外国語語形 → 日本語訳 → Concept

発達後
外国語語形 → Concept
Concept画像 → 外国語語形
Novelの出来事 → 外国語語形
音声 → Concept
```

目標は13言語すべてで母語話者のようになることではない。

目指すもの：

- 読解を中心に1,200 Conceptを横断する
- 日本語正本から各言語への対応を理解する
- 各言語からConceptへ直接到達する
- 場所・画像・物語から語形を想起する
- NovelとEssayの範囲で高いカバー率を得る
- 変換時間と混同率を下げる
- 意味範囲のずれを観測する

## 11. 1,200 Conceptの読み方

1,200 Conceptは少なくない。

```text
1,200 Concept × 14観測面
= 16,800カード相当の対応関係
```

完全に独立した16,800項目ではないが、語形、音声、意味範囲、例文、表記を長期維持するため、相当な学習量となる。

1,200 Conceptは万能語彙ではなく、都市の主要道路を整備する計画である。

### カバー率の概算

効率よく配分された1,200 Conceptの場合、目安は次のとおり。

- JANUS-13内部のNovel・Essay：85〜95％
- 日常会話：85〜92％
- やさしい物語・学習者向け文章：85〜93％
- 一般ニュース：75〜85％
- 一般小説：75〜88％
- 技術・制度・学術文章：65〜80％
- 未知分野の専門記事：60〜75％

これは語形の数え方、対象言語、ジャンル、固有名詞の扱い、語族・見出し語・活用形の区別によって変動する。

### 目標とする読解状態

「辞書なしで全部読む」ことを目標にしない。

> なんとなく読める。なんとなく意味がつかめる。核心語だけ必要に応じて調べられる。

未知語が残っていてよい。文章の骨格が見えれば検索できる。検索した語が何度も戻ってくれば、その時点でConcept候補へ昇格させる。

## 12. 読解レベル

「なんとなく読める」を次の段階で記録する。

### Level 0：不明

話題も出来事も分からない。

### Level 1：話題認識

何について書かれているか分かる。

### Level 2：骨格理解

誰が何をしたか、肯定か否定か、時間関係、原因と結果がおおよそ分かる。

### Level 3：要旨理解

辞書や検索を少し使えば、要旨を日本語で説明できる。

### Level 4：詳細理解

態度、留保、含意、細部まで説明できる。

1,200 Conceptの第一目標は、多くの一般文章をLevel 1〜2で受け止め、少数の検索によってLevel 3へ進めることである。

## 13. Core20以降の「配分」方針

配分の目的は、1,200 Concept以外を覚えないことではない。

> 限られた記憶資源が、名詞、専門語、MEMORIOPOLIS固有語だけへ偏ることを防ぐ。

Core10は名詞中心でよい。Core20以降は、名詞や形容詞のシリーズを続けるのではなく、既存Conceptを文章内で動かす語を早期に入れる。

### 基本原則

> 名詞を10個置いたら、次の10個で名詞を動かす。さらに次の10個で、時間・否定・疑問・比較を加える。

```text
対象を置く：名詞
対象を動かす：動詞
対象を特定する：指示語・疑問語
時間と位置を与える：時間語・空間語
関係を作る：機能語・接続語
評価する：性質・判断・感情
考えを組み立てる：原因・結果・条件・留保
```

## 15. 読解上の仕事による分類

品詞だけでなく、そのConceptが読解で何をするかを記録する。

| 読解機能 | 役割 |
|---|---|
| 対象 | 人、物、場所、出来事を示す |
| 動作 | 何が起きたかを示す |
| 状態 | どのような状態かを示す |
| 指示 | これ、それ、ここなどで対象を特定する |
| 時間 | 前後、継続、完了、頻度を示す |
| 数量 | 一部、全部、増減、程度を示す |
| 論理 | 原因、結果、条件、対比を示す |
| 態度 | 推測、断定、疑問、留保を示す |
| 評価 | 良否、重要性、難易度を示す |
| 検索鍵 | 調べるべき核心語を特定する |

これにより、「形容詞を何語入れたか」だけでなく、「この50 Conceptで未知文章のどの部分が見えるようになったか」を評価する。

## 16. 未知語の扱い

未知語へ遭遇したからといって、すべてをAnkiやCoreへ入れない。

```text
未知語に遭遇
  ├─ その場で調べて終了
  ├─ 発見語としてMarkdownへ記録
  ├─ 再出現待ち
  └─ Core採用候補
```

### Core採用候補への昇格基準

- 複数回出現した
- 文意を決める重要語だった
- 日常でも使える
- NovelとEssayの両方で使える
- 14観測面で比較する価値がある
- 既存Conceptと強く結びつく
- 場所や物語として記憶できる
- 頻出するが毎回検索している

一度しか出ない高度な専門用語は、その場で調べて終えてよい。再出現した場合に候補へ昇格させる。

## 17. Core20の暫定方針

現在のCore10が名詞中心であるため、Core20はCore10を動かすConceptを優先する。

暫定候補：

| Concept ID | 日本語Concept | 主な役割 |
|---|---|---|
| C0011 | ある | 存在 |
| C0012 | する | 実行 |
| C0013 | 持つ | 所有・保持 |
| C0014 | 作る | 生成 |
| C0015 | 送る | 移動・伝達 |
| C0016 | 受け取る | 授受 |
| C0017 | 見る | 知覚 |
| C0018 | 確認する | 一般的な確認行為 |
| C0019 | ここ | 場所指示 |
| C0020 | 誰 | 主体への疑問 |

例：

```text
ここに記録がある。
誰が通知を送ったのか。
私は返信を受け取った。
署名を確認する。
その人は権限を持っている。
人工知性が新しい記録を作る。
```

### Concept境界の注意

「確認する」と既存の「検証」は区別する。

- 確認：状態、内容、存在などを確かめる一般的な行為
- 検証：証拠や手順に基づき、正しさや妥当性を調べる行為

暫定候補は、Core20制作時に日本語正本、Novel、Essay、各言語での実現可能性を確認して最終決定する。

## 20. カバー率の測定

単純な既知語数だけでなく、次を分けて測る。

### 語形カバー率

文章中の語形を見て認識できる割合。

### Conceptカバー率

文中で必要な意味Conceptを識別できる割合。

### 認識カバー率

対象言語の文字または音声から、日本語またはConceptへ到達できる割合。

### 産出カバー率

日本語、Concept ID、Concept画像、Novelの場面から対象言語を出せる割合。

### 構文カバー率

否定、時制、条件、比較、関係節、受動、格、語順、主題・焦点などを認識できる割合。

### 領域カバー率

Novel、日常生活、技術、社会制度、歴史、文化、教育、仕事、自然、感想、比較、批評など、扱える領域の範囲。

### 内容理解率

内容の要点、因果関係、筆者の主張を日本語で説明できる割合。

## 24. 五年計画

### 周期

```text

```

- 約28日：各言語へ約20 Concept
- 1年：240 Concept／言語
- 4年：960 Concept／言語
- 5年：1,200 Concept／言語

### 段階

1年目：240 Concept  
都市の住所体系と基本語。

2年目：480 Concept  
短文の関係構造、時間、否定、比較、日常生活。

抽象語、制度語、読書・ニュース・思考語。

4年目：960 Concept

5年目：1,200 Concept
